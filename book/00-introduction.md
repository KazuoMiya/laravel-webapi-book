# はじめに

本書のゴールは、ログイン機能付きのタスク管理APIを、自分の手で最後まで作り上げることです。考えた仕様をLaravelで形にし、テストで確かめ、本番で動かすための構成と公開後に見守るための手順までを、1つのアプリを少しずつ大きくしながら体験します。

## Web APIが果たす役割

Webページが人の目に向けて画面を返すのに対して、Web APIはプログラムに向けてデータを返します。天気予報アプリが最新の予報を表示できるのも、地図アプリが道順を示せるのも、裏側でどこかのWeb APIからデータを受け取っているからです。

Web APIは、通信の約束事にHTTPを、データの書き方にJSONのような広く普及した形式を使います。どちらも特定のプログラミング言語や機種に縛られないため、作った会社や言語が違うシステム同士でも、同じ窓口を通してデータを受け渡せます。

使う側を選ばないことも大きな強みです。ブラウザーやスマートフォンのアプリはもちろん、計測値を送るだけの小さなセンサー機器からでも、同じAPIを呼び出せます。APIを1つ用意しておけば、使う側の種類が増えても、サーバー側を作り直す必要はありません。

## 本書で扱うこと、扱わないこと

Laravelは、画面の表示からデータベースの操作までを1つで担えるフレームワークです。本書ではその中からサーバー側の機能だけを取り出し、Web APIづくりに専念します。画面づくりの解説を思い切って省き、そのぶんのページをAPIの設計、実装、運用に充てています。

とはいえ、APIは呼び出されて初めて役に立ちます。そこで第15章では、ブラウザー向けのReactアプリと、React Nativeで作るスマートフォンアプリから、完成したAPIを実際に呼び出します。Reactの文法は解説しませんが、サンプルコードを通して「使う側からはAPIがどう見えるか」を確かめます。この視点を持つと、なぜその設計にしたのかが納得しやすくなります。

APIを呼び出すのは人が操作する画面だけではありません。第16章では、AIエージェントからもTaskBoardを使えるようにします。AIがAPIの利用者になる時代に、どこまでの操作をどんな権限で任せるかを、実際に設計して確かめます。

## Laravelと組み合わせる道具

実際にAPIを作ろうとすると、データの保存、利用者の確認、入力のチェック、攻撃への備え、公開後のトラブル調査と、考えることが次々に出てきます。Laravelには、データベースを扱うEloquentや、認証を担うSanctumといった頼れる部品がそろっています。それでも、現場で通用するAPIには、フレームワークの外側の道具も欠かせません。本書では、次の道具もLaravelと組み合わせて使います。

| 道具 | 何のために使うか | 登場する章 |
| --- | --- | --- |
| Docker | 誰のパソコンでも、同じ開発環境をコマンドで再現する | 第3章 |
| OpenAPI | APIの仕様を、人も機械も読める形で書き残す | 第6章 |
| 自動テスト | 手を加えても、APIが壊れていないことを確かめ続ける | 第13章 |
| ログと監視 | 公開後のAPIで何が起きているかをつかむ | 第17章 |
| Laravel Boost | AIコーディング支援に、プロジェクトとLaravelの情報を渡す | 第14章 |
| Laravel MCP | AIエージェントから呼べる「ツール」としてAPIの機能を公開する | 第16章 |

## 対象読者

本書はプログラミング初学者を対象としています。プログラミング経験がほとんどなくても読み進められるよう、第2章で本書に必要な範囲のPHPの基礎から説明します。

前提とするのは、パソコンの基本操作と、ファイルを編集できるテキストエディターを用意できることだけです。ターミナル（コマンドを入力する画面）の使い方は第3章で手順を示します。エディターはVisual Studio Codeを推奨します。

新人研修やチームの勉強会の教材としても使えるよう、各章に演習とレビュー観点を用意しました。講師やチームリーダーの方は、付録の研修カリキュラムと評価の観点もあわせて参照してください。

## 本書の構成

本書は5つの部、18の章で構成されています。前の章で作ったものを次の章で使うため、最初から順番に読むことをおすすめします。第10章までは個人用のタスク管理APIで基礎を固め、第11章からはチームで共有するAPIへと育てていきます。

| 部 | 章 | 身につくこと |
| --- | --- | --- |
| 第1部 準備 | 第1章〜第4章 | HTTPとWeb APIの基本、PHPの基礎、Docker環境の構築、Laravelの基本 |
| 第2部 設計 | 第5章〜第6章 | リソースとURLの設計、エラー形式、OpenAPIによる仕様書 |
| 第3部 実装 | 第7章〜第12章 | データベース、CRUD、入力検証、認証と認可、チームでの共有、セキュリティ対策 |
| 第4部 品質と開発の進め方 | 第13章〜第14章 | 自動テストとCI、AIと一緒に開発する方法 |
| 第5部 利用と運用 | 第15章〜第18章 | ReactとAIエージェントからの利用、ログと監視、デプロイ、障害対応 |

## 各章の読み方

どの章も同じ型でそろえています。本文に加えて、次の要素が登場します。

| 要素 | 置き場所 | 内容 |
| --- | --- | --- |
| この章のゴール | 章の冒頭 | この章を終えるとできるようになること |
| つまずきポイント | 本文の途中 | 初学者が止まりやすい点と、その抜け方 |
| 設計判断メモ | 本文の途中 | 決めたこと、選ばなかった案、その理由、見直す条件 |
| AIに頼むなら | 章末の前 | AIへの依頼の例と、受け取った結果で確かめる点 |
| 演習 | 章末 | 基礎と応用の2問。解答例は付録にまとめています |

設計判断メモは、本書の大きな特徴です。入門書では「こう書く」という結論だけが示されがちですが、現場では複数の案から1つを選び、その理由を説明する場面がほとんどです。選ばなかった案と見直す条件まで知っておくと、状況が変わったときに自分で判断し直せます。

## 研修で使う場合

各章の演習は課題として、レビュー観点はコードレビューと評価の基準として、設計判断メモはグループでの議論の題材として使えます。付録に10日間の新人研修を想定したカリキュラムの例と評価の観点を、第18章に障害のふりかえりのひな形を載せています。

## サンプルアプリ「TaskBoard API」

本書を通して、タスク（やること）を管理するWeb API「TaskBoard API」を作ります。ユーザーは登録とログインをしたうえで、自分のタスクだけを作成、閲覧、更新、削除できます。タスクには期限、優先度、完了状態、タグを付けられます。

完成時のAPIは次のとおりです。各APIの意味は第5章で詳しく設計します。

| メソッド | URL | 内容 | ログイン |
| --- | --- | --- | --- |
| POST | /api/v1/register | ユーザー登録 | 不要 |
| POST | /api/v1/login | ログインしてトークンを受け取る | 不要 |
| POST | /api/v1/logout | ログアウト（トークンを無効化） | 必要 |
| GET | /api/v1/me | ログイン中のユーザー情報 | 必要 |
| GET | /api/v1/tasks | タスク一覧（絞り込み、並べ替え、ページング） | 必要 |
| POST | /api/v1/tasks | タスクの作成 | 必要 |
| GET | /api/v1/tasks/{id} | タスクの詳細 | 必要 |
| PATCH | /api/v1/tasks/{id} | タスクの部分更新 | 必要 |
| DELETE | /api/v1/tasks/{id} | タスクの削除 | 必要 |
| GET | /api/v1/tags | 自分のタグ一覧 | 必要 |

第11章では、このAPIにチームで共有する機能を加えます。チームの作成、メンバーの招待、役割ごとの権限、担当者の割り当て、同時編集の衝突の検出です。追加するAPIは第11章で一覧にします。上の表のAPIの形は変えないので、すでに作ったアプリはそのまま動き続けます。

## 動作環境

本書のコードは、2026年11月時点の次の環境を前提にしています。PHPやMySQLはDockerのコンテナー内で動くため、パソコンへ直接インストールする必要はありません。

| 項目 | バージョン | 備考 |
| --- | --- | --- |
| OS | macOS、Windows 11（WSL2）、Linux | Windowsは第3章の手順でWSL2を使う |
| Docker Desktop | 最新版 | 開発環境のすべてをコンテナーで動かす |
| PHP | 8.5 | Sailの標準。Laravel 13は8.3以上で動作 |
| Laravel | 13.x | 2026年3月リリースの最新メジャー版 |
| MySQL | 8.4 | Laravel Sailの標準構成 |
| Node.js | LTS版 | 第15章のReactでのみ使用 |

Laravelは毎年1回メジャー版を出し、その間は機能追加を小さな更新（マイナー版）で続けています。本書の内容は13.xの範囲であればそのまま動く想定です。

インストールしたパッケージの正確なバージョンは、Composerなら composer.lock、npmなら package-lock.json に記録されます。チームや研修で同じ環境を再現するときは、これらのファイルも一緒に共有してください。

## 本書の表記

- 行頭の `$` はターミナルで入力するコマンドを表します。`$` 自体は入力しません。
- コード中の `// ...` は、それまでと変わらない部分の省略を表します。
- ファイル名はコードの直前に、プロジェクトのフォルダーからの相対パスで示します。
